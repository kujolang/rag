# AI Provider and Model Drift Controls

## Purpose

This gate detects unexpected runtime drift for AI-enabled paths by enforcing pinned provider/model settings and validating known reference prompts from release evaluation output.

## Gate Script

Run:

```bash
kujo run scripts/run_ai_provider_model_drift_check.kujo --interpreter
```

The script reads the latest release-evaluation report and produces a drift artifact.

## Inputs

- Drift controls: `config/ai_provider_model_drift_controls.json`
- Release report: `results/release_eval_report.json` (generated by `scripts/run_release_evaluation.kujo`)

Configurable paths are available in `.env.example`:

- `KUJO_RAG_AI_DRIFT_CONTROLS_PATH`
- `KUJO_RAG_AI_DRIFT_RELEASE_REPORT_PATH`
- `KUJO_RAG_AI_DRIFT_REPORT_PATH`

## Controls File

`expected_runtime` pins provider/model values. Values are exact-match unless set to `*`.

- `embedding_provider`
- `ai_embed_endpoint`
- `ai_embed_model`
- `chat_endpoint`
- `chat_model`

`reference_cases` define known prompt expectations by release-eval case id:

- `id`
- `expected_ok`
- `expected_policy_reason`
- `min_citations`
- `min_confidence`
- `expected_confidence_band`

`min_reference_cases` requires a minimum number of reference prompts to prevent empty-control bypass.

## Failure Behavior

The gate fails when any condition is violated:

- release report missing/unreadable
- dataset version mismatch (if pinned)
- provider/model pin mismatch
- insufficient reference case count
- reference prompt output expectations fail

On failure, the script exits non-zero and still writes `results/ai_provider_model_drift_report.json` for triage.

## Validation

- `kujo run tests/test_ai_provider_model_drift_check.kujo --interpreter`
- `kujo run scripts/run_release_evaluation.kujo --interpreter`
- `kujo run scripts/run_ai_provider_model_drift_check.kujo --interpreter`
